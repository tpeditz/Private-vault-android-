07. DATA INTEGRITY AND SESSION FIXES THAT MUST NOT BE OMITTED
========================================================================

These additional findings came from an earlier source review. Recheck them in
the current source; if already fixed, show the regression evidence.

N01 - Cross-vault primary-key collisions.
Earlier EncryptedRecordEntity made recordId the global primary key, while Room
inserts used REPLACE and restore preserved IDs. Restoring the same ID into slot 1
could replace a slot-0 row. A small host SQLite reproduction confirmed that
conflict behaviour; it was not a physical-device exploit test.
Enforce per-vault record identity with a composite key (vault_slot, record_id)
or reviewed opaque storage identity. Add non-destructive migrations and ensure
all DAO writes/queries/deletes are vault-scoped. Test intentionally identical IDs
in both vaults and verify the other vault's rows/ciphertexts stay unchanged.

N02 - Silent omission of corrupted records.
Earlier decryptEntityOrNull plus mapNotNull could silently omit unreadable
records during export and omit then delete them during a full-slot merge rewrite.
Make authentication/parse failures explicit. Abort ordinary backup/merge on
unexpected corruption and preserve original ciphertext. Never call an incomplete
recovery export a complete backup or overwrite unreadable records silently.

N03 - Late unlock reopens after screen-off/manual lock.
Earlier unlock jobs were not cancelled/invalidated by lock before repository
openSession completed. Serialize KDF requests and bind every authentication
attempt to a request generation invalidated by lock, screen-off or supersession.
Check atomically before session opening; synchronous KDF completion may outlive
coroutine cancellation. A stale successful result must wipe temporaries and
leave Locked. Extend operation checks through write commits/UI publication.

N04 - APK metadata failure accepted as success.
Earlier getPackageArchiveInfo(null result) entered a production fallback for JVM
tests and constructed VerifiedCandidateApk from manifest versions anyway. Fail
closed if actual package/version data cannot be validated. Inject test doubles
in tests instead of creating a release verification bypass. Retain true apksig
signature verification and installed-signer trust checks.

N05 - Decoy password reconfiguration erases data.
Earlier 'configure or update decoy password' created a fresh DEK and deleted all
existing decoy records. Separate initial provisioning, authenticated password
change and destructive reset. Preserve data for a password change; if the
independent old decoy key/password is needed, request it only inside the app's
secure flow. A reset must be labelled destructive and explicitly confirmed.

N06 - Partial setup/configuration mutations.
Several DAO calls are not one logical transaction merely because each insert is
atomic. Stage setup/decoy changes and commit related envelopes/records together.
Coordinate Keystore side effects with a recoverable order. Inject interruption
between steps; never silently recreate existing keys after failure.

N07 - Build reproducibility and debug/release separation.
The earlier ZIP lacked wrapper scripts/JAR and CI published debug artifacts as
