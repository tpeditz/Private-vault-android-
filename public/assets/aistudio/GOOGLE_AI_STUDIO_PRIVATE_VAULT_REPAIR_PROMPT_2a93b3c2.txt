D. PRIORITY 1 — FIX MALFORMED BACKUP RESTORE DATA LOSS (PV-DATA-001)
========================================================================

Current code in `PortableBackupEngine.decryptAndVerifyBackupBytes` does this:
`root.optJSONArray("records") ?: JSONArray()`

This converts a missing or wrong-typed records property into an empty backup. The Replace path deletes existing records for the target slot and inserts the parsed list. That can turn an invalid backup into an empty-vault restore.

Implement strict validation:
- The root JSON object must contain a `records` property.
- The property must be a JSON array, not null, a string, object, boolean or number.
- An explicit `records: []` may remain a valid empty backup if the product supports empty backups. Distinguish it from a missing/bad field.
- Every array element must be a valid supported record object.
- Validate required fields, record types, IDs, duplicate IDs, lengths, folder references, version values and any additional metadata before any database mutation.
- Reject invalid input with a clear message. Do not turn malformed data into an empty list.
- Preserve current authenticated AES-GCM validation and KDF bounds. Do not weaken checks to make test fixtures pass.
- Do not make any database write until all backup records have been authenticated, parsed, validated and bound to the target session/slot.
- Keep Replace and Merge transaction semantics and preserve records in the other vault.
- If a correctly authenticated backup has zero records and Replace is selected, show a deliberate confirmation explaining that the selected target vault will become empty. Do not surprise-delete records.
- Do not log note text, credentials or decrypted payloads in parser errors.

Required regression tests:
1. Valid non-empty backup round-trip.
2. Valid `records: []` backup, if supported.
3. Missing `records` property.
4. `records: null`.
5. `records` provided as string/object/number/boolean.
6. Array with null/non-object/malformed records.
7. Duplicate record IDs and invalid folder references.
8. Wrong password, tag tampering, truncated header/body, unsupported schema and oversized values.
9. For every malformed or unauthenticated backup, assert the target database rows and the other slot remain unchanged.
10. Test Replace and Merge in both primary and decoy slots.
